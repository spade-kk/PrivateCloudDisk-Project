# 安全设计文档

## 1. 安全架构总览

系统采用 **纵深防御** 策略，从网关层到数据层共四道安全防线：

```
┌──────────────────────────────────────────────────┐
│  第一道防线：网关层                                 │
│  JWT 签名验证 · 分布式限流 · 请求头清洗 · CORS       │
├──────────────────────────────────────────────────┤
│  第二道防线：业务服务层                              │
│  BCrypt 密码哈希 · 登录失败锁定 · 人机验证 · API 防护 │
├──────────────────────────────────────────────────┤
│  第三道防线：文件服务层                              │
│  操作凭证 JWT · 并发控制 · 下载授权 · 完整性校验      │
├──────────────────────────────────────────────────┤
│  第四道防线：数据层                                 │
│  外键约束 · 乐观锁 · 软删除 · 审计日志               │
└──────────────────────────────────────────────────┘
```

## 2. 认证与鉴权

### 2.1 JWT 认证流程

```
用户登录 → 验证密码 → 签发 JWT (RSA-256) → 返回 Token
                                              ↓
后续请求 → 网关 JWT 验证 → 提取 X-User-Id → 透传业务服务
```

### 2.2 JWT 配置

| 属性 | 值 |
|------|-----|
| 算法 | RSA-256 |
| 有效期 | 24 小时 |
| 载荷 | `sub`(用户ID), `iat`(签发时间), `exp`(过期时间) |
| 密钥管理 | 公私钥对，网关持有公钥验证，业务服务持有私钥签发 |

### 2.3 操作凭证 (Operation Token)

文件上传/下载操作需要额外的操作凭证，与用户 JWT 分离：

| 属性 | 值 |
|------|-----|
| 算法 | RSA-256 |
| 有效期 | 1 小时 |
| 速率限制 | 300 次请求 |
| 并发限制 | 通过 Redis Lua 原子控制 |

## 3. 密码安全

### 3.1 双层哈希架构

系统采用 **前端预哈希 + 后端二次加密** 的双层密码架构：

```
原始密码
    ↓
前端 PBKDF2-SHA256
  - 算法: SHA-256
  - 迭代: 600,000 次
  - Pepper: "clouddrive-pbkdf2-v1-pepper"
  - 输出: 64 位 hex 字符串
    ↓
后端 BCrypt
  - 轮数: 12 rounds
  - 输入: 前端 PBKDF2 的 hex 输出
  - 输出: $2b$12$... (存入数据库)
```

### 3.2 设计理由

- **PBKDF2**: 内存密集型，抵抗 GPU 暴力破解
- **BCrypt**: 自适应盐值，12 rounds 提供足够安全性
- **双层哈希**: 即使数据库泄露，攻击者无法直接暴力破解原始密码
- **Pepper**: 固定 pepper 存储在代码中，与数据库分离

详见 [密码加密流程文档](./password-encryption.md)。

## 4. 防暴力破解

### 4.1 登录失败锁定

| 策略 | 配置 |
|------|------|
| 账号维度 | 连续失败 5 次 → 锁定 15 分钟 |
| IP 维度 | 连续失败 20 次 → 锁定 30 分钟 |
| 全局维度 | 1 分钟内全局失败 100 次 → 启用增强验证 |

### 4.2 注册频率限制

| 策略 | 配置 |
|------|------|
| IP 维度 | 每小时最多注册 10 次 |
| 全局维度 | 每天最多注册 1000 次 |

## 5. API 安全

### 5.1 分布式限流

网关层实现 7 条限流规则（固定窗口算法）：

| 规则 | 维度 | 限制 |
|------|------|------|
| 全局 | 所有请求 | 1000 次/秒 |
| 登录 | IP | 10 次/分钟 |
| 注册 | IP | 3 次/分钟 |
| 文件上传 | 用户 | 100 次/分钟 |
| 文件下载 | 用户 | 200 次/分钟 |
| API 查询 | 用户 | 300 次/分钟 |
| 凭证申请 | 用户 | 30 次/分钟 |

### 5.2 API 滥用防护

- 请求频率异常检测
- 用户行为模式分析
- 自动触发人机验证

### 5.3 请求头安全

- 防止 X-Forwarded-For 伪造
- 防止 X-User-Id 注入（仅网关可设置）
- 内部 API 必须携带 X-Internal 头

## 6. 数据安全

### 6.1 主键安全

- 全局使用 `BINARY(16)` 存储 UUID
- 不可遍历，防止 ID 枚举攻击
- 自增 ID 仅用于内部日志和审计表

### 6.2 软删除机制

- 文件删除先进入回收站（软删除）
- 30 天后自动清理
- 配额同步更新（乐观锁版本号控制）

### 6.3 审计日志

| 审计类型 | 记录内容 |
|----------|----------|
| 登录审计 | 账号、IP、设备、时间、结果 |
| 操作审计 | 管理员操作类型、目标、结果 |
| 安全事件 | 异常登录、暴力破解、API 滥用 |

## 7. 传输安全

- 生产环境强制 HTTPS (TLS 1.2+)
- HSTS 头配置
- WebSocket 使用 WSS 加密
- 文件传输使用分片加密（可选）

## 8. 客户端安全

### 8.1 密码预哈希

所有客户端（Web、桌面、移动端）在发送密码前均执行 PBKDF2 预哈希，确保密码明文不离开客户端。

### 8.2 凭证存储

| 平台 | 凭证存储方式 |
|------|-------------|
| Web | localStorage (JWT) |
| macOS | Keychain |
| iOS | Keychain |
| Android | EncryptedSharedPreferences |
| Windows | Windows Credential Manager |
| Electron | electron-store (加密) |

### 8.3 设备指纹

- 浏览器指纹 (FingerprintJS)
- 设备唯一标识
- 新设备登录通知
